# AI 学生：讲课、五题前后测与理解检验

基于 Huricha01 的本地改进版，保留原有讲课、五种学生人格、学科挑战和抢答游戏。

## 使用

解压后打开 index.html。也可以在本目录运行 python -m http.server 8000，通过 http://localhost:8000 打开。调用模型需要填写自己的 API Key、OpenAI 兼容地址和模型 ID，且服务商需要允许浏览器跨域调用。

更新 GitHub Pages 时，请一起上传 index.html、learning.js、learning.css、quiz.js、studio.js、studio.css、sprites.js 与 assets 文件夹，保持相对位置。

## 小雅的挑战表情

平时用 normal，抢到或接过作答机会用 handup，只有等待模型回答时才切到 thinking；开始说答案后不再被思考定时器覆盖。小雅答对用 win，答错用 surprise，玩家答对或接手作答时小雅用 confused；lose 留给整局失利。双方都答错后本题结束，不反复交还机会。

立绘在开始挑战时预加载，加载完成后才切换；同图不重复跳动，旧图片请求或上一题的模型回复不会覆盖当前状态。图片加载失败时回退到 normal，若也不可用则保留上一张图。运行 `node tests/game-sprites.test.cjs` 检查资源名、加载竞争、快慢响应、选择／主观题两条路径和回合切换。本测试使用模拟响应，不调用付费模型。

## 互动备课台（2026-10-31）

首页新增「异分母分数相加」与「概率和频率」两套开课模板，带入知识点、初始误区、手动检验题与可编辑的参考标准。模板标准是示例，正式使用前仍应人工核对。原有自选学科、人格与答题挑战继续可用。

- 点击模板进入新课；建议先完成前测，再讲解。教学路线显示当前建议步骤，不自动发起测验。
- 顶栏「互动备课」可打开分数条和公平骰子实验。分数条支持通分观察；掷骰子模拟展示理论概率与实验频率，每次 60 次，最多 6000 次，可重置。
- 「把这组观察放入讲解草稿」只填入输入框，修改后手动发送。教师参考答案与反思笔记不会自动发送给 AI 学生；白板结果也不会直接进入考试请求。
- 反思笔记和白板数值随知识点保存到本课历史，恢复历史可继续操作；它们也包含在原有 JSON 导出中。旧历史无此数据时按默认值创建。
- 模板、白板和笔记不调用模型，不产生模型 API 费用。聊天与测验仍按原来的模型设置和调用次数执行。

交互设计参考 [DeepTutor](https://github.com/HKUDS/DeepTutor) 的学习工作台与任务组织，以及 [OpenMAIC](https://github.com/THU-MAIC/OpenMAIC) 的互动实验与教师引导。本次独立实现轻量前端交互，没有移植其后端或模型代理运行时。

## 讲课与检验

1. 选择学科，在「学习记录」中添加知识点、初始误区和可靠的参考知识／通过标准。手动题可留空，每节课最多六个知识点。
2. 在讲解前点击「组卷并做五题前测」。B 一次生成前后两套题面不同的试卷，每套覆盖概念解释、基本操作、误区纠正、情境迁移与适用边界。A 独立作答，再由 B 核验，共三次调用。成功的前测不会重复执行；失败可手动重试。
3. 给当前选中的 AI 学生讲解，然后点击「课后五题检验」，使用已生成的第二套试卷作答、核验，共两次调用。出题后可由教师检查题目与标准，但不要照着课后题讲答案。
4. 页面展示五个维度的通过情况、原始作答、核验理由与逐字证据。缺题、重复题号、无效格式、通过结论缺少原文证据以及接口错误，都不计为通过。
5. 有完整前后测且模型、服务商、人格、预习条件一致，期间有新增讲解时，才展示前后变化。已经讲过的知识点不能补做前测，仍可做标注为无前测的课后检验。重复课后检验会保留每次记录，不能视为新的独立实验。
6. 手动检验题仍支持单题作答与核验。再次讲解会将当前知识点改回待检验；更换人格会重置对话和所有前后测进度，保留目标配置。
7. 「导出学习记录」下载 JSON，包含讲解、完整试卷、前后测记录、用量、模型及请求耗时，不包含 API Key 或图片原件。当前不支持导入。

## 模型 A 与 B

默认复用同一个模型，但不同角色始终使用独立请求。API 设置可选填同一服务商下的模型 B，负责组卷、核验和总结评价；学生 A 负责聊天及独立作答。B 的输入／输出单价单独填写，未填则标注费用未完整估算。

参考答案、评分标准及历史测验答案均不注入 A 的考试请求。A 可以看到老师的真实讲解和当前对话；前测本身不修改其对话记忆，也不算一次讲授。B 的组卷依据是填写的可靠参考知识，不直接把老师的聊天内容当作真值。

检验是自动模拟，不能证明模型像真人一样学习，也不能证明真实学习者的长期掌握或迁移。建议使用未在讲解中原样示范的题目，并人工核对参考标准。研究仍需要独立前后测及延迟测验。

## 评价与费用

每轮分数标注为「模型参考评分」。总评要求引用消息或检验证据；未提供具体课标时标注未核验。最终评价仍为模型生成，可能有误。图片不会送入最终评价，只标注数量。

设置中填写输入／输出单价（人民币元／百万 tokens），按接口返回的用量估算。未填价格或缺少用量时明确提示。搜索、缓存差价等没有自动计算，以账单为准。每次返回记录模型、单价、用量和耗时。

历史最多保存 30 次会话，可恢复学习状态和用量，兼容旧历史；图片原件不保留。API Key 存在浏览器 localStorage，请求时发给配置的服务商，网页没有独立后端。

## 接口

仅支持 OpenAI Chat Completions 兼容协议。Gemini 预设已改为兼容入口；Claude 需自行配置兼容网关。服务商对思考、联网参数的支持不同，开启开关不保证执行对应能力。

## 验证

运行 `node tests/learning.test.cjs` 和 `node tests/quiz.test.cjs`：检查教学前置条件、A/B 参考隔离、五维覆盖、3+2 调用预算、无前测与条件变化、无效评分、失败恢复及人格重置。

运行 `node tests/studio.test.cjs`：检查模板不消耗调用或占用前测资格、教学路线状态、笔记保存与隔离、分数通分、骰子模拟上限与重置、草稿不自动发送。

已用本地模拟接口检查添加目标、五题前测、讲解、五题课后测、A/B 模型路由、分别计费、历史保存与导出。未调用真实付费模型；真实模型的知识边界、题目等价性、评分正确性和服务商兼容性仍需实际配置后验证。

## 结果边界

五题通过不等于理解通透，也不代表真人学习效果。A 可能依赖预训练知识而非本次讲解；B 生成的题目和标准也可能有错。前后题面不同并不保证心理测量意义上的等价。初始分很高、没有讲解也能答对、重复考试、单模型角色相关偏差等情况，都需要人工分析。当前功能用于可观察的模拟检验，不构成正式教育效果实验。
